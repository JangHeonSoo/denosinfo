# Python과 LLM API Key 인증을 통한 웹 UI 자동 테스트 도구 만들기

> 3줄 요약
> - Python + Playwright 조합으로 웹 UI를 자동으로 테스트하는 도구를 직접 만들 수 있다.
> - LLM API Key를 환경변수로 안전하게 관리하고, 테스트 실패 시 LLM이 셀렉터를 스스로 복구한다.
> - Streamlit으로 웹 UI를 씌우면 누구나 쉽게 사용 가능한 완성형 도구가 된다.

---

## 왜 만들어야 하나

테스트 자동화가 귀찮은 이유는 딱 하나다. UI가 조금만 바뀌면 스크립트 전체가 박살난다. `#submit-btn`이 어느 날 갑자기 `#submit-button-v2`로 바뀌는 순간, 그동안 쌓아온 테스트 코드는 그냥 쓰레기가 된다.

그런데 LLM을 테스트 루프 안에 붙이면 얘기가 달라진다. 셀렉터가 없어지면 LLM한테 "지금 DOM 봐, 버튼 어디 있어?"라고 물어보면 된다. 말하자면 테스트 코드에 자가치유 능력을 심는 것이다.

2025–2026년 기준으로 Playwright + LLM 조합은 QA 현장에서 실제로 쓰이고 있고, Alumnium 같은 라이브러리는 이 구조를 아예 패키지로 묶어버렸다. 직접 만드는 게 더 자유롭고, 어떤 LLM API든 꽂아서 쓸 수 있다.

---

## 전체 구조 설계

```
[Streamlit Web UI]
 ↓ (URL 입력, API Key 입력, 테스트 시나리오 입력)
[테스트 오케스트레이터 (Python)]
 ↓
[Playwright 브라우저 드라이버]
 ↓ (요소 못 찾으면)
[LLM API (OpenAI / Gemini / Anthropic)]
 ↓ (새 셀렉터 반환)
[재시도 로직]
 ↓
[결과 리포트 (Streamlit 화면 + HTML)]
```

컴포넌트는 총 4가지다: Streamlit UI, 테스트 엔진, Playwright 드라이버, LLM API 클라이언트. 각자 역할이 분리되어 있어서 LLM만 바꿔 끼우는 것도 가능하다.

## 환경 세팅

Python 3.10 이상이 필요하다. 패키지는 아래 명령어 하나로 끝난다.

```bash
pip install playwright streamlit openai python-dotenv pytest-playwright
playwright install chromium
```

프로젝트 루트에 `.env` 파일을 만들고 API Key를 넣어둔다. 절대 코드에 직접 박지 않는다. 이건 선택이 아니라 규칙이다.

```
# .env
OPENAIAPIKEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
GEMINIAPIKEY=AIzaSyxxxxxxxxxxxxxxxx
LLM_PROVIDER=openai # openai | gemini | anthropic
TARGET_URL=https://example.com
```

`.gitignore`에 `.env`를 반드시 추가한다. GitHub에 API Key 올리면 수분 안에 탈탈 털린다. 실제로 2024년 기준 GitHub에 노출된 API Key의 평균 악용 시간은 5분이다.

## LLM 클라이언트 모듈

LLM 공급사마다 인터페이스가 다르다. 그래서 추상 레이어를 하나 만들어둔다. 어떤 LLM을 갖다 써도 같은 함수로 호출한다.

```python
# llm_client.py
import os
from dotenv import load_dotenv

load_dotenv()

class LLMClient:
 def init(self):
 self.provider = os.getenv("LLM_PROVIDER", "openai")
 self.apikey = self.loadapikey()
 self.client = self.initclient()

 def loadapi_key(self):
 key_map = {
 "openai": "OPENAIAPIKEY",
 "gemini": "GEMINIAPIKEY",
 "anthropic": "ANTHROPICAPIKEY",
 }
 key = os.getenv(keymap.get(self.provider, "OPENAIAPI_KEY"))
 if not key:
 raise ValueError(f"API Key not found for provider: {self.provider}")
 return key

 def initclient(self):
 if self.provider == "openai":
 from openai import OpenAI
 return OpenAI(apikey=self.apikey)
 elif self.provider == "gemini":
 # Gemini는 OpenAI 호환 엔드포인트 사용
 from openai import OpenAI
 return OpenAI(
 apikey=self.apikey,
 base_url="https://generativelanguage.googleapis.com/v1beta/openai/"
 )
 elif self.provider == "anthropic":
 import anthropic
 return anthropic.Anthropic(apikey=self.apikey)

 def ask(self, prompt: str) -> str:
 if self.provider in ("openai", "gemini"):
 response = self.client.chat.completions.create(
 model="gpt-4o-mini" if self.provider == "openai" else "gemini-2.0-flash",
 messages=[{"role": "user", "content": prompt}],
 max_tokens=256,
 )
 return response.choices[0].message.content.strip()
 elif self.provider == "anthropic":
 response = self.client.messages.create(
 model="claude-3-5-haiku-latest",
 max_tokens=256,
 messages=[{"role": "user", "content": prompt}]
 )
 return response.content[0].text.strip()
```

`provider` 하나만 바꾸면 OpenAI, Gemini, Anthropic 전부 대응된다. 실용적인 구조다.

## Self-Healing 테스트 엔진

핵심 로직이다. Playwright가 요소를 못 찾으면 그냥 실패하지 않고 LLM한테 DOM을 던져서 새 셀렉터를 받아 재시도한다.

```python
# test_engine.py
import functools
from playwright.syncapi import syncplaywright, TimeoutError as PlaywrightTimeout
from llm_client import LLMClient

llm = LLMClient()

def selfhealingfind(page, selector: str, description: str = ""):
 """요소를 못 찾으면 LLM에게 DOM 분석을 요청해서 새 셀렉터를 받아온다."""
 try:
 return page.waitforselector(selector, timeout=5000)
 except PlaywrightTimeout:
 print(f"[HEALING] '{selector}' not found. Asking LLM...")
 dom_snippet = page.content()[:3000] # 토큰 한도 고려
 prompt = f"""
현재 웹페이지의 HTML 스니펫이 있다.
찾으려는 요소: "{description or selector}"
현재 사용한 셀렉터: "{selector}" — 이 셀렉터로는 요소를 찾을 수 없었다.

HTML:
{dom_snippet}

위 HTML을 분석하고, 원하는 요소에 해당하는 가장 적합한 CSS 셀렉터를 딱 하나만 반환하라.
다른 설명 없이 셀렉터 문자열만 반환하라.
"""
 new_selector = llm.ask(prompt)
 print(f"[HEALING] LLM suggested: {new_selector}")
 return page.waitforselector(new_selector.strip(), timeout=5000)


def runtestscenario(url: str, scenarios: list[dict]) -> list[dict]:
 """시나리오 목록을 받아 순서대로 실행하고 결과를 반환한다."""
 results = []
 with sync_playwright() as p:
 browser = p.chromium.launch(headless=True)
 page = browser.new_page()
 page.goto(url, timeout=15000)

 for step in scenarios:
 action = step.get("action")
 selector = step.get("selector", "")
 value = step.get("value", "")
 description = step.get("description", selector)
 result = {"step": description, "status": "pass", "error": ""}

 try:
 element = selfhealingfind(page, selector, description)

 if action == "click":
 element.click()
 elif action == "fill":
 element.fill(value)
 elif action == "assert_visible":
 assert element.is_visible(), f"Element not visible: {selector}"
 elif action == "assert_text":
 actual = element.inner_text()
 assert value in actual, f"Expected '{value}' in '{actual}'"

 result["status"] = "pass"
 except Exception as e:
 result["status"] = "fail"
 result["error"] = str(e)

 results.append(result)

 browser.close()
 return results
```

`selfhealingfind` 함수가 핵심이다. Playwright의 `TimeoutError`를 잡아서 DOM을 LLM에게 넘기고, LLM이 반환한 새 셀렉터로 재시도한다. 이 구조 덕분에 UI가 조금 바뀌어도 테스트가 스스로 살아남는다.

## Streamlit 웹 UI 구성

테스트 엔진을 감싸는 웹 인터페이스다. Streamlit을 선택한 이유는 간단하다. Python 코드 50줄이면 완성된다.

```python
# app.py
import streamlit as st
import json
import os
from dotenv import load_dotenv
from testengine import runtest_scenario

load_dotenv()

st.setpageconfig(page_title="LLM Web UI Tester", layout="wide")
st.title("🔍 LLM-Powered Web UI Auto Tester")

# --- 사이드바: 설정 ---
with st.sidebar:
 st.header("⚙️ 설정")
 provider = st.selectbox("LLM Provider", ["openai", "gemini", "anthropic"])
 apikeyinput = st.text_input("API Key", type="password",
 value=os.getenv(f"{provider.upper()}APIKEY", ""))
 if apikeyinput:
 os.environ[f"{provider.upper()}APIKEY"] = apikeyinput
 os.environ["LLM_PROVIDER"] = provider

 targeturl = st.textinput("테스트 대상 URL", value="https://example.com")
 headless = st.checkbox("Headless 모드", value=True)

# --- 메인: 시나리오 입력 ---
st.subheader("📋 테스트 시나리오 (JSON)")
default_scenario = json.dumps([
 {"action": "assert_visible", "selector": "h1", "description": "페이지 제목"},
 {"action": "click", "selector": "a[href]", "description": "첫 번째 링크 클릭"},
], indent=2, ensure_ascii=False)

scenarioinput = st.textarea("시나리오 JSON", value=default_scenario, height=250)

col1, col2 = st.columns([1, 5])
with col1:
 run_btn = st.button("▶ 테스트 실행", type="primary")

if run_btn:
 if not target_url:
 st.error("URL을 입력하라.")
 else:
 try:
 scenarios = json.loads(scenario_input)
 with st.spinner("테스트 실행 중..."):
 results = runtestscenario(target_url, scenarios)

 st.subheader("📊 테스트 결과")
 pass_count = sum(1 for r in results if r["status"] == "pass")
 failcount = len(results) - passcount

 cola, colb, col_c = st.columns(3)
 col_a.metric("전체", len(results))
 colb.metric("✅ 통과", passcount)
 colc.metric("❌ 실패", failcount)

 for r in results:
 icon = "✅" if r["status"] == "pass" else "❌"
 with st.expander(f"{icon} {r['step']}"):
 st.write(f"상태: {r['status'].upper()}")
 if r["error"]:
 st.error(r["error"])

 except json.JSONDecodeError as e:
 st.error(f"JSON 파싱 오류: {e}")
 except Exception as e:
 st.error(f"테스트 실행 오류: {e}")
```

실행은 터미널에서 한 줄이다.

```bash
streamlit run app.py
```

## 보안 처리 포인트

API Key 관리는 대충 하면 안 된다. 실제 서비스에서 주의해야 할 지점 3가지다.

1. 환경변수 우선 원칙
코드에 API Key를 절대 하드코딩하지 않는다. `os.getenv()`로만 불러온다. Streamlit 배포 환경이라면 Streamlit Cloud의 Secrets 관리 기능을 쓴다.

2. Key 유효성 검증
앱 시작 시 API Key가 없으면 바로 예외를 던진다. 실행 중간에 인증 실패로 터지는 것보다 훨씬 낫다.

```python
key = os.getenv("OPENAIAPIKEY")
if not key:
 raise ValueError("OPENAIAPIKEY가 설정되지 않았다.")
```

3. DOM 토큰 한도 관리
LLM에 DOM을 통째로 넘기면 토큰 비용이 폭발한다. `page.content()[:3000]` 처럼 잘라서 보낸다. 어차피 LLM은 첫 3,000자 안에서 셀렉터를 충분히 추론할 수 있다.

## 실전 테스트 시나리오 예시

로그인 페이지 테스트를 JSON으로 표현하면 이렇다.

```json
[
 {
 "action": "assert_visible",
 "selector": "input[name='username']",
 "description": "유저명 입력 필드 노출 확인"
 },
 {
 "action": "fill",
 "selector": "input[name='username']",
 "value": "testuser@example.com",
 "description": "이메일 입력"
 },
 {
 "action": "fill",
 "selector": "input[type='password']",
 "value": "password123",
 "description": "비밀번호 입력"
 },
 {
 "action": "click",
 "selector": "button[type='submit']",
 "description": "로그인 버튼 클릭"
 },
 {
 "action": "assert_text",
 "selector": ".dashboard-title",
 "value": "대시보드",
 "description": "로그인 후 대시보드 문구 확인"
 }
]
```

5개 스텝이다. 이 중에서 `button[type='submit']` 셀렉터가 사라져도 LLM이 DOM을 분석해서 다른 버튼 셀렉터를 찾아준다. 사람이 손댈 일이 없다.

## 확장 아이디어

이 도구를 베이스로 더 발전시킬 수 있는 방향들이다.

- CI/CD 연동: GitHub Actions에서 `python -m pytest`로 호출해서 PR마다 자동 실행
- 스크린샷 diff: 테스트 전후 스크린샷을 비교해서 시각적 회귀 검출
- 자연어 시나리오 생성: "로그인 테스트 시나리오 만들어줘"라고 LLM에게 요청하면 JSON 자동 생성
- 멀티 LLM 비교: 같은 DOM에 대해 OpenAI와 Gemini가 각각 어떤 셀렉터를 제안하는지 비교

세 번째 방향이 가장 실용적이다. 시나리오 작성 자체를 LLM에게 맡기면 QA 엔지니어는 검토만 하면 된다.
