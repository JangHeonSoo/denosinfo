## 코드를 잊는다는 것

2025년 2월 2일, X(구 트위터)에 올라온 짧은 글 하나가 개발 생태계를 뒤흔들었다. 전 테슬라 AI 디렉터이자 OpenAI 공동 창립자인 Andrej Karpathy가 이렇게 썼다.

> "코드가 존재한다는 사실조차 잊고, 직관과 분위기에 완전히 빠져들어 개발하는 새로운 방식. 나는 이걸 바이브 코딩(Vibe Coding)이라고 부른다."

그 트윗은 조회수 510만 회, 좋아요 3만 개를 기록했다. 한 달도 안 되어 Merriam-Webster 사전에 "속어 및 트렌드" 명사로 등재됐다. 그냥 유행어가 아니었다. 뭔가를 정확하게 짚어낸 표현이었다.

---

## 바이브 코딩, 뭐가 다른가

"AI로 코드 짜는 거 아니야?" — 반은 맞고 반은 틀리다.

기존 AI 보조 코딩은 개발자가 구체적인 명령을 내리는 방식이다. "이 함수에서 파라미터는 userId이고, 반환 타입은 User 객체여야 하며, try-catch로 예외 처리해줘." 정확하고 명시적이다. 바이브 코딩은 다르다. "사용자 프로필 페이지에 필요한 비동기 함수 만들어줘. FastAPI 스타일로, 성능 중시하고 현대적인 코드로." 이렇게 분위기(Vibe) 를 전달한다.

개발자의 역할이 '코드 생산자'에서 '설계자이자 품질 관리자'로 바뀐다. Karpathy 본인은 이렇게 묘사했다.

> "그냥 보고, 말하고, 돌리고, 붙여 넣는다. 대부분 된다."

오케스트라 지휘자를 생각하면 이해하기 쉽다. 지휘자는 바이올린 운지법을 하나하나 지시하지 않는다. "더 장엄하게", "조금 더 애절하게" — 그 분위기를 전달할 뿐이다.

---

## 숫자로 보는 현실

허황된 이야기가 아니라는 증거는 이미 쌓였다.

- 개발자 74% 가 바이브 코딩 방식 도입 후 생산성 향상을 보고했다.
- 작업 완료 속도 51% 단축 — 특히 CRUD API, UI 컴포넌트, 보일러플레이트 코드에서 효과가 두드러진다.
- 비개발자 63% 가 직접 앱을 만들며 소프트웨어 민주화가 현실화되고 있다.
- 2024년 기준, 전 세계 코드의 41%가 AI 생성 코드다. 숫자로는 2,560억 줄.
- 바이브 코딩 시장은 2024년 47억 달러에서 2032년 370억 달러 규모로 성장이 전망된다.

그렇다고 장밋빛만은 아니다. AI 생성 코드의 45%에서 보안 취약점 이 발견된다는 연구 결과도 있다. 2025년 5월에는 특정 플랫폼으로 만든 앱 10%에서 개인정보 유출 취약점이 드러났다. 실제로 개발자 63%는 AI 코드 디버깅에 직접 짜는 것보다 더 많은 시간을 쓴 경험이 최소 한 번 있다고 답했다.

실전에서 유용한 건 맞다. 만능은 아니다.

## 핵심 도구 3종 비교

바이브 코딩을 시작하려면 도구 선택이 먼저다. 2026년 현재 실무에서 가장 많이 쓰이는 세 가지를 비교하면 다음과 같다.

| 도구 | 성격 | 가격 | 강점 | 실전 성공률 |
|------|------|------|------|------------|
| Cursor | VS Code 기반 AI 에디터 | Free / Pro $20/월 / Pro+ $60/월 | 프로젝트 전체 맥락 파악, 멀티파일 수정, 정확도 85–90% | 92% |
| Windsurf | VS Code 기반 AI IDE (Codeium 제작) | Free 25크레딧/월 / Pro $15/월 | Cascade 에이전트, 크레딧 기반 진입 장벽 낮음 | 78% |
| GitHub Copilot | VS Code/JetBrains 확장 플러그인 | $10–19/월 | 기존 IDE 그대로 유지, 인라인 자동완성 강점 | 68% |

현업 개발자들 사이에서 가장 많이 추천받는 건 Cursor다. 전체 저장소 인덱싱과 Auto-Run 검증 기능 덕분에 실전 활용률이 가장 높다. 반면 처음 바이브 코딩에 입문하는 경우라면 Windsurf의 무료 크레딧이 심리적 진입 장벽을 낮춰준다.

## 윈도우 환경 세팅 가이드

### Cursor (Windows)

1. cursor.sh 접속 → Download 클릭 (Windows 자동 감지, `.exe` 파일 다운로드)
2. 설치 마법사 실행 → 모든 기본값 유지로 설치
3. 시작 메뉴에서 Cursor 실행
4. 첫 실행 시 VS Code 설정 가져오기 가능 (기존 사용자라면 강력 추천)
5. `Ctrl + L` → AI 채팅 패널 열기
6. `Ctrl + I` → Agent Mode 진입 (멀티파일 수정 가능)
7. `Ctrl + K` → 인라인 편집 모드

> 팁: Python 환경 세팅 시 반드시 "Add Python to PATH" 옵션을 체크할 것. 나중에 터미널에서 `python` 명령이 안 잡히는 가장 흔한 실수다.

### Windsurf (Windows)

1. windsurf.com 접속 → x64 인스톨러 다운로드
2. 설치 시 "Add to PATH" 옵션 체크 필수
3. 설치 완료 후 첫 실행 → VS Code 설정/키 바인딩 가져오기 선택
4. Codeium 계정 가입 (무료 플랜으로 시작 가능)
5. `Ctrl + L` → Cascade 에이전트 패널 열기
6. 에이전트 모드 선택 후 자연어로 작업 지시

## 맥 환경 세팅 가이드

### Cursor (macOS)

1. cursor.sh 접속 → macOS용 `.dmg` 파일 다운로드
2. `.dmg` 열기 → Cursor 아이콘을 Applications 폴더로 드래그
3. 처음 실행 시 보안 경고가 뜰 수 있음: 시스템 환경설정 → 보안 및 개인정보보호 → "그래도 열기" 클릭
4. `Cmd + L` → AI 채팅 패널
5. `Cmd + I` → Agent Mode
6. `Cmd + K` → 인라인 편집

> 팁: M4 MacBook 사용 시 추가 설정 없이 바로 네이티브 성능으로 동작한다. Homebrew로 Python 먼저 설치해두는 게 이후 작업에 훨씬 편하다. 터미널에서 `brew install python` 한 줄이면 된다.

### Windsurf (macOS)

1. windsurf.com → macOS용 인스톨러 다운로드
2. 설치 후 첫 실행 → VS Code 설정 가져오기 (선택)
3. Cascade 에이전트 패널: `Cmd + L`
4. 무료 25크레딧/월로 시작, 사용량 파악 후 Pro($15/월)로 업그레이드 고려

## 실전 바이브 코딩 워크플로

설치가 끝났다고 바로 잘 되진 않는다. 프롬프트를 어떻게 쓰느냐가 결과의 80%를 결정한다. 실무에서 검증된 순서가 있다.

1단계 — 스펙 먼저, 프롬프트 나중

코드 작성 요청 전에 10–15분을 투자해 스펙을 적는다. "무엇을 만드는가, 누구를 위한 것인가, 핵심 기능은 무엇인가." 이 단계를 건너뛰면 AI와의 대화가 산으로 간다.

2단계 — 작게 쪼개서 요청

"전체 기능 다 만들어줘"는 실패의 지름길이다. "라우팅 1개 + 테스트 1개"처럼 PR 단위로 쪼갤수록 결과 품질이 올라간다.

3단계 — Rules 파일 설정

Cursor와 Windsurf 모두 Rules 기능을 제공한다. 프로젝트 전반에 걸쳐 AI가 따를 지침을 정의하는 일종의 시스템 프롬프트다. "TypeScript만 사용할 것", "주석은 한국어로 달 것" 같은 규칙을 여기에 넣는다. 이 단계를 빠뜨리면 AI가 매번 다른 스타일로 코드를 생성하는 혼란이 생긴다.

4단계 — 커밋은 아낌없이

바이브 코딩에서 Git은 생명줄이다. 작동하는 변경 사항이 생길 때마다 커밋한다. AI가 뭔가를 망가뜨리기 전에 저장해두는 것이다. "커밋 전 프롬프트 입력"을 습관으로 만들면 나중에 시간을 크게 아낄 수 있다.

5단계 — 20분 룰

AI가 5번 이상 같은 오류를 반복하면 직접 코드를 수정하는 것이 더 빠르다. 바이브 코딩의 속도는 집착이 아니라 전략적 선택에서 나온다.

---

## 이런 용도에 특히 강하다

모든 작업에 쓰는 건 비효율이다. 다음 용도에서 시간 단축 효과가 가장 두드러진다.

- 보일러플레이트 코드 — 81% 빠름 (최고 효율 구간)
- API 연동 및 데이터 파싱 — 67% 빠름
- UI 컴포넌트 생성 — 51% 빠름
- MVP 프로토타입 — 며칠 만에 시각화 가능
- 내부 운영 툴, 간단한 SaaS — 비개발자도 직접 구축 가능

반대로 복잡한 알고리즘, 보안 핵심 코드, 대규모 레거시 리팩토링은 AI보다 직접 작성이 나을 때가 많다. 실제로 보안 핵심 코드에서의 생산성 향상은 12%에 그치며, 검증 시간이 더 오래 걸리는 경우가 많다.

## 실제 사례 하나

인디 해커 Pieter Levels는 바이브 코딩으로 17일 만에 연간 반복 매출(ARR) 약 13억 원을 달성했다. 코드를 직접 한 줄도 짜지 않고, 오직 AI와의 대화로만 제품을 만들었다. 뉴욕타임스 기자는 비전문가로서 여러 앱을 바이브 코딩으로 제작하며 "한 사람을 위한 소프트웨어 시대"를 예고하기도 했다.

Karpathy는 2025년 말 회고에서 이렇게 말했다.

> "바이브 코딩은 소프트웨어를 지형 개조할 것이고, 직업 설명을 바꿔놓을 것이다."

그 변화는 이미 시작됐다.
