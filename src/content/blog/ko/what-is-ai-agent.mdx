## 사람처럼 일하는 소프트웨어가 등장했다

2025년 1월, OpenAI가 'Operator'라는 이름의 AI 에이전트를 공개했다. 웹 브라우저를 스스로 조작하며 항공권을 예매하고, 식료품을 장바구니에 담고, 레스토랑을 예약한다. 사람이 마우스와 키보드로 하던 일을 AI가 대신 하는 것이다. 같은 해 Anthropic의 Claude는 컴퓨터 화면을 직접 보고 클릭하고 타이핑하는 'Computer Use' 기능을 선보였다. Google도 'Project Mariner'라는 웹 브라우징 에이전트를 내놨는데, 한 번에 최대 10개 작업을 동시에 처리한다.

![추상적인 형상의 빛나는 기하학적 오브젝트와 상호작용하는 정교한 기계 팔](/images/aiagentheroroboticarmlight1772754166221.png)

사실 이건 챗봇의 진화가 아니다. 완전히 다른 물건이다.

챗봇은 물어보면 대답한다. 거기서 끝이다. 하지만 AI 에이전트는 목표를 받으면 스스로 계획을 세우고, 필요한 도구를 꺼내 쓰고, 결과를 확인한 뒤 다음 행동을 결정한다. 비유하자면 챗봇이 "백과사전"이라면, AI 에이전트는 "신입사원"에 가깝다. 아직 서툴지만, 시킨 일을 알아서 해온다.

<br/>

## 그래서 AI Agent가 정확히 뭔데

AI Agent는 대형언어모델(LLM)에 추론 능력, 도구 사용, 메모리를 결합한 자율 소프트웨어 시스템이다. 단순히 텍스트를 생성하는 게 아니라, 환경을 인식하고 판단하고 행동까지 한다.

![AI의 구성 요소(두뇌, 기억 등)를 상징하는 정교하고 빛나는 검은색 회로 기판](/images/aiagentarchitecturecircuitmacro_1772754189842.png)

핵심 구성요소는 네 가지다:

- 두뇌(Foundation Model): GPT-4o, Claude, Gemini 같은 대형언어모델이 인지 엔진 역할을 한다. 자연어를 이해하고, 복잡한 지시를 추론하며, 다단계 계획을 세운다.
- 기억(Memory): 단기 기억(컨텍스트 윈도우)과 장기 기억(과거 대화, 학습된 스킬)을 갖는다. 2026년 기준, 에피소드 기억(과거 상호작용), 의미 기억(지식 베이스), 절차 기억(습득 기술) 세 가지 유형으로 분화했다.
- 도구(Tools): 웹 브라우저, 코드 실행기, 데이터베이스, 캘린더, API 등 외부 시스템과 연결된다. Anthropic이 만든 MCP(Model Context Protocol)라는 오픈 표준 덕분에, 하나의 프로토콜로 수십 가지 도구를 통합할 수 있게 됐다.
- 행동(Action): 추론 결과를 바탕으로 실제 클릭, 입력, API 호출 같은 행위를 실행한다. 단순 출력이 아니라 세상에 영향을 미친다.

<br/>

## 생각하고, 행동하고, 돌아보는 루프

AI 에이전트의 작동 원리를 이해하려면 ReAct(Reasoning + Acting) 패턴을 알아야 한다. IBM이 정리한 바에 따르면, 이 패턴은 사고 연쇄(Chain of Thought)와 외부 도구 사용을 결합한 것이다.

작동 방식은 이렇다:

1. 생각(Thought): "사용자가 서울에서 부산까지 KTX 표를 예매해달라고 했다. 먼저 코레일 사이트에 접속해야겠다."
2. 행동(Action): 코레일 웹사이트를 열고, 출발지/도착지/날짜를 입력한다.
3. 관찰(Observation): 검색 결과를 확인한다. 오전 9시 열차가 있다.
4. 다시 생각: "좌석이 남아있는지 확인하고, 가격도 체크해야 한다."

이 루프가 목표 달성까지 반복된다. 사람이 문제를 푸는 방식과 꽤 닮았다. 생각하고, 시도하고, 결과를 보고, 다시 생각한다. 실수하면 스스로 교정도 한다. OpenAI의 Operator가 웹사이트에서 막히면 자체 추론 능력으로 다른 경로를 찾는 것도 이 패턴 덕분이다.

<br/>

## 챗봇, 코파일럿, 에이전트 — 뭐가 다른 건가

생성형 AI의 진화는 크게 세 단계로 나뉜다.

| 구분 | 시기 | 특징 | 대표 사례 |
|------|------|------|-----------|
| 1세대: 콘텐츠 생성 | 2022~2023 | 질문에 텍스트/이미지 생성. 단방향 | ChatGPT, DALL-E |
| 2세대: 코파일럿 | 2024~2025 | 앱 내에서 작업 보조. 사용자 지시 필요 | GitHub Copilot, MS 365 Copilot |
| 3세대: AI 에이전트 | 2026~ | 자율적 계획·실행·학습. 멀티스텝 워크플로우 | Operator, Claude Computer Use, Project Mariner |

그런데 여기서 한 걸음 더 나간 개념이 있다. Agentic AI다. AI 에이전트가 '특정 업무를 맡은 개별 전문가'라면, Agentic AI는 '여러 전문가가 팀을 이뤄 협업하는 시스템 전체'를 가리킨다. 오케스트레이터가 각 에이전트에 역할을 배분하고, 에이전트끼리 결과를 주고받으며 복잡한 목표를 달성한다.

<br/>

## 숫자로 보는 AI Agent 시장

뜬구름 잡는 이야기가 아니다. 돈이 움직이고 있다.

- 기업용 AI 에이전트 소프트웨어 시장: 2025년 15억 달러(약 2조원) → 2030년 418억 달러(약 61조원). 5년 만에 28배, 연평균 성장률 175%다.
- Gartner 전망: 2026년까지 전체 기업 애플리케이션의 40%가 AI 에이전트를 통합한다. 2025년엔 5%도 안 됐다. 1년 만에 8배 점프.
- Gartner 추가 예측: 2028년까지 최소 15%의 업무 결정이 AI 에이전트에 의해 자율적으로 이루어진다. 2024년엔 사실상 0%였다.
- McKinsey 설문(2025): 62%의 조직이 이미 AI 에이전트를 실험 중이다.
- 멀티 에이전트 시스템 관련 문의: 2024~2025년 사이 1,445% 증가.

백문이 불여일견이라고, 투자 규모만 봐도 이 시장이 얼마나 빠르게 달리는지 알 수 있다.

## 지금 실제로 쓰이는 AI Agent들

이론이 아니라 이미 돌아가고 있는 것들이다.

OpenAI — ChatGPT Agent(구 Operator): 2025년 1월 출시 후 7월에 ChatGPT에 통합됐다. CUA(Computer-Using Agent) 모델 기반으로, GPT-4o의 비전 능력과 강화학습 기반 추론을 결합했다. 웹 브라우저 스크린샷을 "보고" 마우스/키보드 액션으로 "조작"한다. 항공편 예약, 온라인 쇼핑, 음식 배달 주문 등을 자동 처리하며, 신용카드 입력 같은 민감한 작업은 사용자에게 제어권을 넘긴다.

Anthropic — Claude Computer Use: 2024년 10월 공개. 화면을 직접 보고 마우스를 움직이고 키보드를 치는 방식이다. Anthropic의 공동창업자 Jared Kaplan은 "모델이 사람이 쓰는 모든 도구를 활용하는 새로운 단계에 진입했다"고 말했다. 실제로 Claude가 VS Code를 열어 웹사이트를 만들고, 터미널에서 서버를 실행하는 데모가 공개되기도 했다.

Google — Project Mariner: Google I/O 2025에서 공개됐다. 비전-언어 모델 기반으로 텍스트뿐 아니라 버튼, 그래프, 이미지까지 이해한다. 'Teach and Repeat' 기능이 인상적인데, 사용자가 작업을 한 번 시연하면 유사한 작업을 자동으로 반복한다. Ticketmaster, StubHub, Resy 등과 파트너십을 맺고 실제 서비스에 적용 중이다.

의료 분야: Microsoft의 AI 진단 오케스트레이터(MAI-DxO)는 복잡한 의료 케이스에서 85.5% 정확도를 달성했다. 숙련된 의사의 평균이 20%라는 점을 생각하면 상당한 수치다.

한국 기업들: SK텔레콤의 '에이닷(A.)'은 음성 기반 개인 비서로 멀티모달 확장 중이다. 네이버는 하이퍼클로바X 기반으로 추론·기억·지속대화 실험을 진행한다. KT는 AI 컨택센터(AICC)에서 자동 보고서 작성, 스케줄 관리 에이전트를 적용했다. LG CNS는 'AgentWorks' 플랫폼을 출시해 코딩 없이도 업무 에이전트를 만들 수 있게 했다.

## AI Agent를 만드는 도구들

개발자라면 프레임워크가 궁금할 수밖에 없다. 2025~2026년 기준 주요 AI 에이전트 프레임워크를 정리했다.

| 프레임워크 | 개발사 | 특징 | 적합한 용도 |
|------------|--------|------|-------------|
| LangChain / LangGraph | LangChain | 100개 이상 LLM 연동, 그래프 기반 워크플로우 | 복잡한 멀티스텝 에이전트, RAG 파이프라인 |
| AutoGen | Microsoft | 멀티에이전트 대화, 코드 자동 생성·실행 | 에이전트 간 협업, 코드 기반 문제 해결 |
| CrewAI | CrewAI | 역할 기반 멀티에이전트 협업 | 팀 워크플로우 자동화 |
| AutoGPT | AutoGPT | 완전 자율 운영, 장기 메모리 | 장기간 독립 실행 작업 |
| Semantic Kernel | Microsoft | C#/Python/Java 지원, 엔터프라이즈 보안 | 기존 소프트웨어에 AI 통합 |
| Langflow | Langflow | 로우코드, 시각적 인터페이스 | 빠른 프로토타이핑, RAG 워크플로우 |

그리고 이 생태계를 하나로 묶는 접착제가 바로 MCP(Model Context Protocol)다. Anthropic이 2024년 11월에 오픈소스로 공개한 이 프로토콜은, AI 모델과 외부 도구 사이의 연결을 표준화한다. 예전에는 도구 하나마다 별도 통합 코드를 짜야 했다. MCP 덕분에 한 번 구현하면 수십 가지 도구와 바로 연결된다. Block, Apollo, Replit, Sourcegraph 같은 기업이 이미 도입했다.

## 아직 넘어야 할 산

![세련된 실버 메탈 기기들이 조화롭게 배치된 밤의 테크 가든](/images/aiagentfuturetechgardennight1772754214899.png)

장밋빛 전망만 있는 건 아니다. 현실적인 문제가 꽤 있다.

- 신뢰성: Princeton 대학의 연구자 Ofir Press는 "에이전트 AI는 장기 계획과 실수 복구에서 여전히 어려움을 겪는다"고 지적했다. 실제로 OpenAI Operator나 Project Mariner 모두 아직 느리고 실수가 잦다는 평가를 받는다.
- 보안: 에이전트가 자율적으로 웹을 돌아다니면, 피싱이나 프롬프트 인젝션 공격에 노출될 위험이 커진다. OpenAI는 Operator에 의심스러운 활동 감지 시 실행을 중단하는 모니터링 시스템을 넣었다.
- 비용과 인프라: 정교한 에이전트를 돌리려면 상당한 컴퓨팅 자원이 필요하다. SLM(Small Language Model)과 효율적 모델 라우팅이 해결책으로 떠오르고 있다.
- 거버넌스: Deloitte 보고서에 따르면 90% 이상의 기업이 AI 거버넌스 개선 필요성을 인식하고 있다. 자율성이 높아질수록 투명성, 공정성, 책임 소재가 더 중요해진다.
- 일자리 문제: 소 잃고 외양간 고치는 격이 되지 않으려면, 에이전트가 대체할 업무와 사람이 집중할 업무를 지금부터 구분해야 한다.

## 2026년, 그리고 그 이후

MS는 모든 직원이 AI 에이전트를 관리하는 '에이전트 보스(Agent Boss)'가 되는 미래를 그린다. Gartner는 2028년이면 업무 결정의 15%가 AI 에이전트 손에 넘어간다고 본다. 어떤 사람에겐 기회고, 어떤 사람에겐 위협이다.

확실한 건, AI 에이전트가 더 이상 실험실 안의 프로토타입이 아니라는 거다. 이미 고객 상담을 하고, 코드를 짜고, 진단을 돕고, 티켓을 예매하고 있다. 2026년은 AI가 '도구'에서 '동료'로 바뀌는 전환점이 될 가능성이 높다.

호랑이 등에 올라탔으면 내릴 수 없다. 방향은 정해졌다.
