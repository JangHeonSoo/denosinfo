## Forgetting the Code Exists

On February 2, 2025, a single post on X (formerly Twitter) shook the developer ecosystem. Andrej Karpathy — former Tesla AI Director and OpenAI co-founder — wrote:

> "There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."

That tweet hit 5.1 million views, 30,000 likes. Within a month, Merriam-Webster listed it as a trending slang noun. Not just a buzzword. It named something people were already feeling.

---

## What Makes Vibe Coding Different

"Isn't it just AI writing code?" — Half right, half wrong.

Traditional AI-assisted coding still requires explicit commands: "Create a function where the parameter is userId, the return type is a User object, and wrap exceptions in try-catch." Precise and directive. Vibe coding flips that. "Make an async function for the user profile page. FastAPI style, performance-first, modern and clean." You're transmitting a vibe — not a spec sheet.

The developer's role shifts from code producer to product designer and quality controller. Karpathy himself described it:

> "I just see stuff, say stuff, run stuff, and copy-paste stuff, and it mostly works."

Think of an orchestra conductor. They don't dictate every fingering position on every instrument. They communicate a feeling — "more majestic," "a touch more melancholy" — and let the musicians interpret. That's exactly the vibe coding relationship with AI.

The evidence is piling up fast.

- 74% of developers report productivity gains after adopting vibe coding approaches.
- 51% faster task completion — especially for CRUD APIs, UI components, and boilerplate code.
- 63% of vibe coding users are non-developers building apps directly — software democratization is real.
- 41% of all global code in 2024 was AI-generated — that's 256 billion lines.
- The vibe coding market is projected to grow from $4.7B in 2024 to $37B by 2032.

And 63% of developers admit they've spent more time debugging AI code than they would have writing it themselves — at least once.

Useful in practice? Absolutely. A silver bullet? Far from it.

## Windows Setup Guide

### Cursor (Windows)

1. Visit cursor.sh → Click Download (auto-detects Windows, downloads `.exe`)
2. Run the installer wizard → Keep all defaults
3. Launch Cursor from the Start Menu
4. On first launch, import VS Code settings if you're an existing user (strongly recommended)
5. `Ctrl + L` → Open AI chat panel
6. `Ctrl + I` → Enter Agent Mode (multi-file edits)
7. `Ctrl + K` → Inline editing mode

> Tip: When setting up Python, always check "Add Python to PATH" during installation. Missing this is the #1 cause of `python` not being recognized in the terminal later.

### Windsurf (Windows)

1. Visit windsurf.com → Download the x64 installer
2. During installation, check "Add to PATH" — this is critical
3. On first launch, choose to import VS Code settings and key bindings
4. Sign up for a Codeium account (free plan available)
5. `Ctrl + L` → Open Cascade agent panel
6. Select Agent mode and give natural language instructions

## macOS Setup Guide

### Cursor (macOS)

1. Visit cursor.sh → Download the macOS `.dmg` file
2. Open `.dmg` → Drag the Cursor icon into the Applications folder
3. On first launch, if you see a security warning: System Preferences → Security & Privacy → "Open Anyway"
4. `Cmd + L` → AI chat panel
5. `Cmd + I` → Agent Mode
6. `Cmd + K` → Inline editing

> Tip: On M4 MacBook, Cursor runs natively with no extra config. Pre-installing Python via Homebrew (`brew install python`) saves headaches in later sessions.

### Windsurf (macOS)

1. Visit windsurf.com → Download macOS installer
2. After installation, import VS Code settings on first launch (optional but convenient)
3. Cascade agent panel: `Cmd + L`
4. Start with the free 25 credits/month plan, then evaluate upgrade to Pro ($15/mo) based on usage

## The Practical Workflow

Installation done doesn't mean results follow. How you prompt determines 80% of the output quality. Here's the workflow that holds up in production:

Step 1 — Spec first, prompt second

Spend 10–15 minutes writing a spec before asking for any code. What are you building? Who is it for? What are the core features? Skip this and the AI conversation drifts sideways.

Step 2 — Break it down

"Build the whole feature" is a trap. Slice requests into PR-sized pieces — "one route + one test" — and quality improves dramatically.

Step 3 — Configure your Rules file

Both Cursor and Windsurf offer a Rules feature. This is where you define persistent instructions for the AI — a system prompt that governs the entire project. "TypeScript only," "comments in Korean," "no inline styles." Skip this step and the AI generates inconsistent code on every session.

Step 4 — Commit early, commit often

In vibe coding, Git is a lifeline. Commit every time something working is produced. Make "commit before prompting" a muscle memory habit — it makes rollbacks trivial when AI breaks something.

Step 5 — The 20-minute rule

If the AI repeats the same error more than five times, just write the code yourself. Vibe coding's speed comes from strategic decisions, not stubborn persistence.

## Where It Shines Most

Using it everywhere is inefficient. These use cases show the sharpest time savings:

- Boilerplate & configuration code — 81% faster (peak efficiency zone)
- API integration & data parsing — 67% faster
- UI component creation — 51% faster
- MVP prototyping — visualize in days, not weeks
- Internal ops tools, simple SaaS — buildable without a developer background

The flip side: complex algorithms, security-critical code, and large-scale legacy refactoring often take longer with AI than without. Security-critical code shows only a 12% productivity gain — and verification overhead frequently wipes that out.
