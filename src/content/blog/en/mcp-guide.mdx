## 1. Why MCP Exists

Plain LLMs have a frustrating ceiling. They don't know what happened after their training cutoff, can't touch the file system, and have no way to call external APIs. MCP punches through that ceiling.

Model Context Protocol is an open-source protocol introduced by Anthropic in November 2024. It has since been adopted by Claude, ChatGPT, Cursor, GitHub Copilot, and dozens of other AI applications. The reason it spread fast is simple: before MCP, every AI app had to build its own custom integrations for every external system. MCP standardizes that entire layer, so developers write one MCP server and every MCP-compatible AI app can use it.

One sentence captures it:

> MCP = a standardized protocol for LLMs to access external tools and data

## 2. Architecture: Host · Client · Server

Three actors make up the MCP architecture.

| Component | Role | Real Examples |
|---|---|---|
| Host | The AI app users interact with. Manages Clients and enforces security policy. | Claude Desktop, Cursor, VS Code |
| Client | Lives inside the Host. Maintains a 1:1 connection with a specific MCP Server. Routes JSON-RPC messages. | Claude's internal MCP module |
| Server | Exposes Tools (callable functions), Resources (read-only data), and Prompts (reusable templates). | Weather server, DB server, GitHub server |

The data flow looks like this:

```
User → Host (LLM decides) → Client → Server → Result → Host → User
```

Concretely: a user asks Claude Desktop "What's the weather in Seoul today?" The Host (LLM) determines it needs a weather Tool, and the Client sends a JSON-RPC request to the weather MCP Server. The server calls the actual API, returns the result, and Claude turns it into a natural-language answer. The user sees none of this machinery. They just get an answer.

## 3. Under the Hood: JSON-RPC 2.0

MCP uses JSON-RPC 2.0 as its wire format. A request looks like this:

```json
{
 "jsonrpc": "2.0",
 "id": 1,
 "method": "tools/call",
 "params": {
 "name": "get_weather",
 "arguments": { "city": "Seoul" }
 }
}
```

A successful response:

```json
{
 "jsonrpc": "2.0",
 "id": 1,
 "result": {
 "content": [{ "type": "text", "text": "Seoul: 18°C, Clear" }],
 "isError": false
 }
}
```

Two transport mechanisms are supported:

- Stdio (Standard Input/Output): Direct local process communication. Fast, minimal setup. Great for development.
- Streamable HTTP: Remote server communication with real-time streaming. Designed for production.

## 4. Three Core Capabilities of an MCP Server

An MCP server can offer exactly three things.

Tools — Functions the AI calls directly. "Add two numbers", "Search the web", "Query the database." This is the most commonly used feature.

Resources — Read-only data. File contents, database records, API snapshots. The server hands structured context to the LLM.

Prompts — Reusable prompt templates managed server-side. Patterns like "Suggest the next task" can be standardized and versioned on the server.

## 5. Build It — An MCP Server in Under 10 Minutes

### 5-1. Install Dependencies

```bash
pip install mcp fastmcp
```

Requires Python 3.10+. `fastmcp` is the high-level wrapper bundled with the official MCP Python SDK. A single decorator registers a Tool.

### 5-2. Write the Server (`server.py`)

Two tools: one that adds numbers, one that returns weather data.

```python
# server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("my-first-mcp")

@mcp.tool()
def add(a: int, b: int) -> int:
 """Add two integers together."""
 return a + b

@mcp.tool()
def get_weather(city: str) -> str:
 """Return weather info for a given city. (Demo — hardcoded values)"""
 weather_data = {
 "Seoul": "18°C, Clear",
 "Busan": "22°C, Cloudy",
 "Jeju": "25°C, Partly Cloudy",
 }
 return weather_data.get(city, f"No weather data found for {city}.")

if name == "main":
 mcp.run(transport="stdio")
```

The `@mcp.tool()` decorator is the entire registration mechanism. The function's docstring becomes the Tool description — this is what the LLM reads to decide when and how to use the Tool.

### 5-3. Write the Client (`client.py`)

Connect to the server, list available Tools, and invoke them.

```python
# client.py
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
 server_params = StdioServerParameters(
 command="python",
 args=["server.py"],
 env=None
 )

 async with stdioclient(serverparams) as (read, write):
 async with ClientSession(read, write) as session:
 await session.initialize()

 # List available Tools
 toolsresponse = await session.listtools()
 print("=== Available Tools ===")
 for tool in tools_response.tools:
 print(f" - {tool.name}: {tool.description}")

 # Call add Tool
 print("\n=== Calling add(3, 7) ===")
 result = await session.call_tool("add", {"a": 3, "b": 7})
 print(f" Result: {result.content[0].text}")

 # Call get_weather Tool
 print("\n=== Calling get_weather('Seoul') ===")
 result = await session.calltool("getweather", {"city": "Seoul"})
 print(f" Result: {result.content[0].text}")

if name == "main":
 asyncio.run(main())
```

### 5-4. Run It

```bash
python client.py
```

Expected output:

```
=== Available Tools ===
 - add: Add two integers together.
 - get_weather: Return weather info for a given city. (Demo — hardcoded values)

=== Calling add(3, 7) ===
 Result: 10

=== Calling get_weather('Seoul') ===
 Result: 18°C, Clear
```

Server and client communicated over Stdio using JSON-RPC. Connect a real Claude Desktop or Cursor instance, and the AI autonomously decides when to invoke these Tools.

## 6. Debugging with MCP Inspector

For a visual interface instead of code, use the MCP Inspector:

```bash
npx @modelcontextprotocol/inspector python server.py
```

Opens at `http://127.0.0.1:6274`. Click a Tool, fill in parameters, see the result. It's the Postman of MCP development — an indispensable workflow accelerator.

## 7. Connect to Claude Desktop

One config file change attaches the server to Claude Desktop.

macOS: `~/Library/Application Support/Claude/claudedesktopconfig.json` 
Windows: `%APPDATA%\Claude\claudedesktopconfig.json`

```json
{
 "mcpServers": {
 "my-first-mcp": {
 "command": "python",
 "args": ["/absolute/path/to/server.py"]
 }
 }
}
```

Restart Claude Desktop. A Tools icon appears in the chat interface. Ask "What is 3 plus 7?" and Claude will invoke the `add` Tool on its own.

## 8. Where to Go Next

| Level | What to Build | Keywords |
|---|---|---|
| Level 1 | Real external API integration | `httpx`, `requests` |
| Level 2 | Expose file system via Resources | `@mcp.resource()` |
| Level 3 | Deploy remotely with Streamable HTTP | `transport="http"` |
| Level 4 | Add authentication | OAuth, Bearer Token |
| Level 5 | Wrap existing FastAPI app as MCP | `fastapi-mcp` library |

The MCP ecosystem exploded in 2025. Hundreds of open-source servers already exist for Slack, GitHub, Notion, PostgreSQL, and more. There's no need to reinvent the wheel — but building one from scratch first is the fastest way to understand how someone else's wheel turns.
